```
  ├── on_balance / on_total_account
  └── (执行端回传) ──► PairTradingContext::OnAlgoOrderUpdate
                          ├── 量/价直接覆盖
                          ├── RiskManager::OnAlgoFinished（终态）
                          ├── SignalGenerator::RecalcOrderParams
                          └── PairInfoManager::ClearActiveAlgoOrder
```

**两个关键不变量**（很多用例就是围着它们转）：

1. **启动闸门**：`Init` 结束在 `Reconciling`，五个交易入口全部直接 `return`；等两腿持仓推送/批次到位、对账通过，才进 `Trading`。原因是价差推送通常早于持仓推送 —— 账本不对就会"在孤儿仓上再开一笔"或"平仓单变反向开仓"。
2. **撤单是异步两段式**：`RequestCancelAlgoOrder` 只把算法单置成 `ALGO_OS_CANCELLING`，之后由执行端撤主动腿、等被动腿成交，子单清零后 `OnAlgoOrderUpdate` 收到终态才释放对子。**调用方不能假设它同步生效。**

## 5. 已知的、与测试无关的遗留缺陷

以下是在写这套用例的过程中顺带发现的，**尚未修复**（不属于"行情→算法单"链路，未纳入本套件）：

1. `AlgoContext.cpp` 三个 catch 块用 `sprintf(msg, "... {}", e.what())` —— `{}` 会原样打印，异常信息丢失。
2. `PairInfoManager::ResetAbnormalCloseState` 的空指针判断写反：`if (!st) { *st = ...; }`。
3. `StrategyConfig.cpp` 把 `mdPassword` 和 Lark webhook token 明文打进日志。
4. **`UpdateOnPosition` 每条持仓推送被跑两遍**（2026-09-30 补 H 组时发现，**尚未修**）：
   `PairTradingContext::OnPosition` 显式调一次 `UpdateOnPosition`，紧接着调的
   `UpdateLiquidStatus(position)` 内部**又调了一次** `UpdateOnPosition`
   （`PairInfoManager.cpp:473-475`）。
   两遍都是幂等写，所以**行为正确、只是白跑**（外加 `pi.modifyTime` 被刷两次）。
   因为纯幂等，用例无法从外部观察，所以没有断言 —— 记在这里而不是当作用例。

## 6. 桩保真度（写桩时踩过的坑）

桩可以少实现，但**不能改变语义** —— 否则用例会"为了错误的原因变绿/变红"。

| 坑 | 症状 | 修法 |
|---|---|---|
| `fmt::format` 桩忽略格式串 | 最早那版直接 `((os << args), ...)`，于是 `fmt::format("{}.{}.{}", "BINANCE", "USDT_SWAP", "DOGE-USDT")` 返回 `"BINANCEUSDT_SWAPDOGE-USDT"`（两个点没了）→ `UpdateOnBalance` 的 `strstr` 永远匹配不上，资金推送的写入被静默吞掉。**I2/I3 就是被这个桩骗红的。** | 桩里实现真正的 `{}` 顺序替换 + `{{`/`}}` 转义（`stubs/ext/fmt/core.h`） |
| `BaseAlgoOrder` 字段集被"概括" | 字段顺序/名称就是 `BuildAlgoOrderJson` 写入的契约，概括了断言就不可靠 | 逐字段照抄真实头文件；真实头里没初值的字段在桩里全部值初始化 |
| `pubsub::Position::exchangeTypeEnum` / `instTypeEnum` 用 `int` | `UpdateOnPosition` 拿它们索引 `ExchangeTypeEnum2StrMap[...]` → 编译失败 | 必须是**枚举类型** |
| `SpreadStatsBuilder::Prune` / `Build` 只声明不定义 | `OnTimer` 链接报 undefined symbol | 把 `signal/SpreadStatsBuilder.cpp` 也软链进来一起编译 |
| 夹具里存 `PairInfo` **值拷贝** | `GetPairInfo()` 返回的是指向 `m_pairInfoMap` 内部的指针，`SubmitAlgoOrder` 通过它改状态 → 断言全看不出来 | 一律取引用 |
